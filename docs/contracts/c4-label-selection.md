# C4 모의 교정 — 라벨 선택 계약 v3

확정: 2026-10-04 (사용자). 근거: D17 사전등록 "라벨 선택: 층화 무작위 / 불확실성 / 불확실성+다양성
(같은 초기 라벨·후보 풀)", 라벨 예산 단위 = query–candidate 쌍에 대한 명시적 판단 1회.
v2 초안은 Codex Astra(high) 검토 1회를 거쳤고, 지적 10건 중 8건을 이 문서에 반영했다(반영 위치는 각 절 끝 `[A#]`).
나머지 2건(능동 정책의 진행 규칙, 학습 seed 공유)은 원칙만 고정하고 세부는 후속 계약에 둔다.

이 계약은 정책 곡선을 보기 전에 고정한다. 결과를 본 뒤 바꾸지 않는다.

## 1. 후보 풀
- 학습셋 순위 파일(고정 SigLIP2 기준선 index, `pr eval --split train`)에서 질의별 상위 20 = 모든 정책의 공통 풀.
- 입력 검증: 질의마다 상품 ID 유일, 후보 ≥ 20, query_id 유일. 위반하면 실패한다(조용히 고치지 않음). `[A2]`
- 순위 파일의 sha256을 실험 namespace에 넣는다. `[A2][A6]`

## 2. 질의 ID
- `query_id`는 정답 상품 ID를 드러내지 않는 불투명 값이다: `f"{source}:{sha256(source, product_id, image_sha)[:16]}"`.
  이전 형식 `source:product_id:sha12`는 53,882 학습 질의 100%에서 정답을 그대로 노출했다. `[A10]`
- 정답 대응(query_id → truth_product_id)은 시뮬레이터(oracle)와 평가 단계만 읽는다. 선택기·라벨 변환·학습은 읽지 않는다.

## 3. 정책
### `stratified` (사전등록 기준 정책)
- 층 = 순위 구간 S1 = 1–5, S2 = 6–10, S3 = 11–20. 학습셋 실측 정답 비율 13.1% / 1.4% / 0.6%를 보고 정했다(기록).
- 난수: `numpy.random.SeedSequence(seed).spawn(3)`로 층마다 독립 생성기(PCG64). 질의는 query_id 정렬 후 층별 독립 순열,
  각 질의에서 그 층의 순위 하나를 균등 선택. `[A1]`
- 전체 순서 = S1, S2, S3를 번갈아 엮은 것. 예산 B의 선택 = 이 순서의 앞 B개 → 층별 균등(±1), 질의당 최대 3판단, 예산 중첩.
- 선택은 정답을 읽지 않는다.
- 구현 고정(2026-10-04): 층마다 `perm = rng.permutation(n)`을 먼저, 그다음 `ranks = rng.integers(lo, hi, size=n)`를 뽑는다
  (`ranks[i]`는 정렬 순서 i번째 질의). 순서를 바꾸면 선택이 달라지므로 이 순서가 계약의 일부다.
- I_s는 같은 seed stratified 실행 출력의 앞 100줄이다(예산 중첩이므로 별도 파일 없음).

### `random` (참고 정책, v1)
- 풀 전체에서 seed 고정 비복원 균등 추출. 주 가설 비교에는 쓰지 않는다. 노이즈·event_id는 §5·§6의 v3 방식을 따른다(v1 출력은 재현되지 않음).
- list_id = sha256(namespace, policy_id, seed, query_id).

### `uncertainty`, `uncertainty+diversity` (후속 계약)
- 원칙만 고정: 정책마다 3,000까지 **하나의 진행 경로**를 만들고 측정 지점에서 관측한다. 배치 크기·재학습 주기·동점 처리는
  실행 전에 후속 계약으로 고정한다. 선택기는 공개 후보 정보와 이미 예산을 쓴 답만 받는다. `[A4][A10]`

## 4. 공유 초기 라벨
- seed s마다 I_s = `stratified` seed s 순서의 앞 100개와 **그 답**. 세 정책 모두 I_s에서 시작한다. `[A3]`
- 예산 B는 초기 100을 포함한 총 판단 수.
- seeds = 0, 1, 2. seed s가 선택·노이즈·재랭커 학습을 함께 묶은 반복 하나다. seed별 초기 재랭커 체크포인트를 정책 간 공유한다(학습 계약에서 세부). `[A5]`

## 5. 답과 노이즈
- 후보 = 정답이면 match, 아니면 not_match.
- 노이즈 p ∈ {0, 0.1, 0.2}: 쌍마다 u = sha256(namespace_base, seed, query_id, product_id)에서 만든 [0,1) 균등값, u < p면 뒤집는다.
  같은 쌍의 답은 정책·예산·실행 순서와 무관하게 같다. `[A3]`
- 대칭 뒤집기라도 클래스 불균형 때문에 관측 match의 오염률은 p와 다르다 — 보고 시 함께 적는다.

## 6. 출력
- FeedbackEvent JSONL, 선택 순서대로. actor = sim, position = 1-based 순위, policy_id ∈ {random, stratified, …}.
- namespace = sha256(계약 버전 "c4-v3", 순위 파일 sha256, 노이즈 p). event_id = sha256(namespace, policy_id, seed, query_id, product_id).
  예산 B는 event_id에 넣지 않는다(예산 간 같은 이벤트 재사용). 노이즈 조건이 다르면 event_id가 다르다. `[A6]`
- 실행 요약(JSON): 계약 버전, namespace, 순위 파일 sha256, 정책, seed, 예산, p, 층별 선택 수, match 수.
- 정답 필드는 출력에 없다.

## 7. 판정 규칙 (사전 고정)
- 평가: 검증셋, 상품 단위 macro R@5. 재랭킹은 상위 20 안에서만 → 상한 = 검증셋 macro R@20 = 0.937. `[A9]`
- 목표 R@5 = 고정 기준선 검증셋 macro R@5 0.857(index f924c1c9ffb3, 상품 3,243 · 질의 6,782) + 0.03 = **0.887** (D17 첫 가설과 같은 값). `[A7]`
- 측정 지점 = 100, 200, 300, 500, 700, 1,000, 1,500, 2,000, 3,000. D17의 4지점(100/300/1,000/3,000)을 포함한다. `[A8]`
- 주 지표 = seed마다 목표에 **처음 도달한 측정 지점**. 100에서 이미 도달하면 "≤100", 3,000까지 미도달이면 "3,000 초과·미도달".
  도달 후 하락은 그대로 기록하고 최초 도달 지점을 바꾸지 않는다. `[A8]`
- 정책 감소율 = 1 − (정책의 seed별 최초 도달 지점 중앙값 / stratified의 중앙값). 미도달 seed가 있으면 감소율을 주장하지 않는다.
