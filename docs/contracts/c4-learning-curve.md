상위 계약: `c4-label-selection.md` v3(정책·예산·노이즈·판정 규칙), `c4-event-labels.md` v1, `c5-reranker-v2.md`.

## 1. 무엇을 재는가
- 가설(D17 첫 가설, c4-v3 §7): 고정 SigLIP2 기준선 위에 교정으로 학습한 재랭커가 검증셋 상품 단위 macro Recall@5를
  **0.887** 이상으로 올린다. 사전 지정 측정 지점 중 어디에서 처음 관측되는지를 본다.
- hypothesis_id = `H1-rerank-r5`, 사전등록 버전 = `c4-v3` (2026-10-04).
- 절대 목표는 계약대로 0.887이다. 반올림하지 않은 기준선(실측 0.85714…)과 Δ를 따로 기록한다 — 0.887 도달이 정확히 +0.03은 아니다. `[R4]`

## 2. 재랭커 고정과 개발 이력 공개 `[R1][R7][R10]`
- 재랭커 = **v2** (`c5-rerank-v2`, 하이퍼파라미터는 그 계약 그대로).
- 개발 이력(전부 개발 검증셋, seed 0, 노이즈 0):
  v0·v1은 예산 300·3,000과 진단용 100,000 라벨에서도 R@5 0.856–0.858로 기준선과 같았다(PR #17·#19).
  v2는 300 / 3,000 / 100,000에서 0.858 / 0.869 / 0.894였다(PR #21). 이 결과를 보고 v2를 골랐다.
- 따라서 이 곡선의 검증셋 수치는 **모델 선택에 쓰인 같은 검증셋**에서 나오고, seed 0은 개발에 노출된 반복이다.
  모든 판정 문장은 "모델 선택에 사용한 개발 검증셋의 관측 결과"로 한정한다. 확증은 §7의 시험셋 절차로만 주장한다.

## 3. 실행 격자 `[R8][R9]`
| 조건 | 정책 | 노이즈 p | seed | 측정 지점 (예산 B) | 용도 |
|---|---|---|---|---|---|
| 주 | stratified | 0 | 0, 1, 2 | 100, 200, 300, 500, 700, 1,000, 1,500, 2,000, 3,000 | **판정** |
| 강건성 | stratified | 0.1, 0.2 | 0, 1, 2 | 같음 | 보조 (판정에 안 씀) |
| 참고 | random | 0 | 0, 1, 2 | 같음 | 보조 (판정에 안 씀) |
- 합계 9 × 3 × 4 = **108개 조건 키**. 실행 전에 키 목록을 `plan.json`에 쓰고, 끝나면 키마다 상태(완료·실패·미실행)를 반드시 남긴다.
  실패한 키를 다시 돌리면 원래 기록을 지우지 않고 시도 번호를 붙인다. 재시도는 같은 설정으로 최대 1회, 사유는 비결정적 오류(입출력 등)일 때만.
- seed s 하나가 선택·노이즈·재랭커 학습을 함께 묶는다(c4-v3 §4): `pr simulate --seed s`, v2 학습 `seed = s`.
- 예산마다 시뮬레이션을 새로 돌리고(`pr labels`, c4-labels-v1), **재랭커는 예산마다 처음부터 학습한다**(이전 체크포인트를 이어 쓰지 않는다).
- 예산 중첩 확인: 같은 seed·정책·노이즈에서 작은 예산의 이벤트가 큰 예산 이벤트의 앞부분과 같은지 검사해 기록한다.
  stratified는 계약상 중첩이어야 하고(다르면 실패), random은 중첩이 보장되지 않으므로 결과만 기록한다.
- random은 공유 초기 라벨(I_s)을 쓰지 않는 참고 정책이다(c4-v3 §3·§4의 "세 정책"에 포함되지 않음). 비교 표에 이 차이를 적는다.

## 4. 한 실행의 측정 `[R3][R6]`
- 학습: 학습셋 순위 파일 + 학습셋 후보 통계 + 그 라벨 → v2. 검증셋은 학습에 쓰지 않는다.
- 평가: 검증셋 순위 파일(index f924c1c9ffb3) 재정렬 → 상품 단위 macro R@1·R@5·R@10·R@20.
- 평가 모집단 고정: 검증 질의 **6,782개 · 상품 3,243개**. 질의 ID 목록의 sha256을 `summary.json`에 적고, 모든 실행에서 재정렬 결과의
  질의 집합이 이것과 완전히 같은지 검사한다(다르면 그 실행은 실패).
- 평균 방식: 상품 안 질의 평균 → 상품 간 같은 가중 평균(macro) → seed 간 같은 가중 산술평균. 한 지점에 실패한 seed가 있으면
  그 지점은 "3-seed 평균"으로 표시하지 않고 성공 seed 수를 함께 적는다.
- 기준선 대비 Δ = 재정렬 R@K − 기준선 R@K. 상품 단위 paired bootstrap(B = 1,000, bootstrap seed 0, 95% 백분위 구간)으로 Δ의 구간과
  "Δ ≤ 0 재표집 비율"을 낸다(기존 `eval.bootstrap` 그대로). 이 구간은 **학습이 끝난 한 모델에 조건부인, 지점별 구간**이다.
  상품을 독립 표집 단위로 본다는 가정 위에 있고, 모델 선택·지점 선택·학습 seed 변동은 반영하지 않는다. "Δ ≤ 0 비율"을 p값이라 부르지 않는다.

## 5. 판정 (c4-v3 §7) `[R4][R5][R9]`
- 주 지표: seed마다 R@5 ≥ 0.887이 **사전 지정 측정 지점 중 처음 관측된 지점**. 100에서 이미 관측되면 "≤100",
  3,000까지 관측되지 않으면 "지정 지점 3,000까지 도달 관측 없음". 측정 지점 사이(예: 400)는 관측하지 않았으므로 주장하지 않는다.
  도달 후 떨어져도 최초 관측 지점은 바꾸지 않고, 떨어진 것도 기록한다.
- 앞선 지점이 실패한 seed는 그 뒤의 도달을 "최초 도달"로 확정하지 않고 "판정 불가"로 둔다.
- 결과 문장: 세 seed 모두 관측 → "도달 관측(중앙값 X, 개발 검증셋)", 일부만 → "일부 도달 관측(k/3)", 하나도 없음 → "미도달".
  같은 지점에서 세 seed가 모두 도달했다는 뜻이 아니므로, seed별 지점을 함께 적는다.
- 불확실성 보조 표기(판정은 바꾸지 않음): 그 지점 Δ 구간의 하한을 **0과 비교**(개선 여부)하고, **0.03과 비교**(+0.03 근거)해 함께 적는다.
- 지속성(보조): 최초 도달 이후 지점들에서 R@5 ≥ 0.887을 유지한 비율.

## 7. 시험셋 확인 절차 (검증 결과를 보기 전에 고정) `[R11]`
- 시점: M1 리포트(#12) 직전 1회. `--final`로 시험셋 index·순위·후보 통계를 만들고, 그 전에는 열지 않는다.
- 평가 대상은 미리 고정: **주 조건(stratified, 노이즈 0)에서 예산 3,000으로 학습한 v2, seed 0·1·2 세 모델** — 검증 곡선 결과로 다른 예산·seed·모델을 고르지 않는다.
- 판정: 시험셋 기준선 macro R@5 대비 세 seed 평균 Δ와 각 seed의 paired bootstrap 구간. 성공 = 세 seed 평균 R@5 ≥ 시험셋 기준선 + 0.03.
  "최초 도달 예산"은 시험셋에서 재현 확인하지 않는다(그 주장은 개발 검증셋 한정으로 남는다).
- 실패·미달도 그대로 보고한다.

## 8. 알려진 한계 `[R2]`
- `query_id`는 공개된 공식(sha256(source, product_id, image_sha))으로 만든 값이라, image_sha와 후보 ID를 아는 코드는 정답을 복원할 수 있다.
  이 프로젝트의 선택기·학습기는 **허용 입력만** 쓴다: 순위 파일의 `query_id`·`top_k_product_ids`·`scores`, 후보 통계, 임베딩 벡터, 라벨.
  해시를 계산하거나 매니페스트의 정답 필드를 읽는 코드가 없음을 테스트(정답 필드 변경 불변)로 확인한다.
  ID를 비밀키 기반으로 바꾸면 c4-v3의 선택 순열이 바뀌므로 이번 실행에서는 바꾸지 않는다.
- 분할 간 같은 이미지·상품 변형 중복은 이 계약에서 다시 검사하지 않는다(분할 단계 검사 결과를 따른다).
