# C4 교정 이벤트 → 라벨 변환 계약 v1

확정: 2026-10-05 (사용자, A안 "교정 존중 + 다수결"). 이슈 #8. 비교한 다른 안: B "엇갈리면 버림(만장일치만)", C "가장 최근 판단 하나". D20 `feedback.build_labels(events) -> Label[]`, `Label` 계약
("충돌(같은 쌍에 match·not_match)은 규칙으로 해소하고 기록")을 구체화한다.
재랭커 학습 결과를 보기 전에 고정한다. 결과를 본 뒤 바꾸지 않는다.

## 1. 입력
- `FeedbackEvent` JSONL(시뮬레이터 `pr simulate` 출력 또는 사람 교정 로그). 정답 대응은 읽지 않는다.
- 쌍 = (query_id, product_id).

## 2. 이벤트 정리
- **중복 제거:** 같은 `event_id`가 여러 번 오면 하나만 쓴다(멱등 키). 같은 event_id인데 내용이 다르면 실패한다(조용히 고르지 않음).
- **변환 대상:** `match`, `not_match`만 라벨이 된다.
- **라벨 없음:** `skip`은 라벨을 만들지 않는다. 노출됐지만 이벤트가 없는 후보(무반응)도 라벨이 없다 —
  관측하지 못한 것은 음성이 아니다. 빌더는 노출 목록을 입력으로 받지 않으므로 무반응을 음성으로 만들 경로 자체가 없다.
- **이번 버전 범위 밖:** `prefer`, `point`는 라벨을 만들지 않고 개수만 기록한다(후속 계약).

## 3. 충돌 해소 (같은 쌍에 match와 not_match가 모두 있을 때)
1. **세션 안 = 마지막 판단:** 같은 `session_id` 안에서는 `ts`가 가장 늦은 판단 하나만 남긴다(같은 ts면 event_id 사전순 마지막).
   사람이 판단을 고친 경우를 교정으로 본다.
2. **세션 사이 = 다수결:** 세션별로 남은 판단을 센다. 많은 쪽이 라벨이 된다.
3. **동수 = 라벨 없음:** match 세션 수와 not_match 세션 수가 같으면 그 쌍은 라벨을 만들지 않는다.
- 가중치 `weight` = 이긴 쪽 세션 수 / 판단한 세션 수 (충돌이 없으면 1.0).
- `origin_events` = 그 쌍에서 쓴 모든 match·not_match 이벤트의 event_id(정렬). 세션 안에서 덮인 판단도 포함한다.
- `skip`은 같은 세션의 앞선 판단을 덮지 않는다(개수만 센다).
- 시간대 없는 `ts`는 UTC로 읽는다.
- 보고서의 충돌 = 중복 제거 후 그 쌍에 match와 not_match가 모두 있는 경우(세션 안 번복 포함). 항목마다 세션별 최종 판단, 해소 결과(pos·neg·none), 관련 event_id를 적는다.

## 4. 출력
- `Label` JSONL, (query_id, product_id) 정렬. kind ∈ {pos, neg}.
- `label_version` = sha256("c4-labels-v1", 정렬된 입력 event_id 목록)의 앞 12자리. 같은 입력이면 같은 버전.
- 보고서 JSON(`<out>.report.json`): 계약 버전, label_version, 입력 이벤트 수, 중복 제거 수, action별 수,
  pos·neg 수, 라벨 없는 쌍 수(skip만 / 동수 / prefer·point만), 충돌 목록(쌍, 세션별 최종 판단, 해소 결과, 관련 event_id).
- 시뮬레이터 출력은 쌍마다 판단이 하나라 충돌이 0이어야 한다 — 보고서로 확인한다.

## 5. 검증 (완료 기준)
- 무반응·skip이 neg가 되는 경우 0 (테스트).
- 세션 안 번복, 세션 사이 다수결, 동수, 같은 event_id 중복, 같은 event_id 다른 내용(실패)을 각각 테스트한다.
- 같은 입력을 순서만 바꿔 넣어도 출력과 label_version이 같다.
